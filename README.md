# Inmebel

Inmebel — платформа для выбора и заказа мебели. Покупатель просматривает каталог, добавляет товары в избранное и корзину, отправляет заявки на изготовление и отслеживает заказы. Мастерская публикует товары и обрабатывает поступившие заявки и заказы. Администратор управляет каталогом, категориями, атрибутами, пользователями и заказами.

## Состав проекта

| Каталог | Назначение | Стек |
| --- | --- | --- |
| [`api/`](api/) | REST API, авторизация и роли, каталог, расчёт стоимости, заявки, корзина и заказы | Laravel 12, PHP 8.3, PostgreSQL 16 |
| [`frontend/`](frontend/) | Сайт покупателя и личный кабинет мастерской | Next.js 15, React 19, TypeScript |
| [`admin/`](admin/) | Панель администратора | React 19, Vite, TypeScript |

В API маршруты разделены на общие (`/api`), клиентские (`/api/client`), мастерской (`/api/workshop`) и административные (`/api/admin`). Доступ к личным разделам ограничен авторизацией и ролью пользователя. Основные сценарии видны в файлах [`api/routes/`](api/routes/).

## Возможности

- Каталог мебели с категориями, атрибутами, поиском и фильтрами.
- Регистрация и вход для клиентов и мастерских.
- Избранное, отзывы, корзина и оформление заказов для клиентов.
- Заявки на изготовление мебели, расчёт цены и отслеживание статусов.
- Управление товарами, заявками и заказами в кабинете мастерской.
- Управление пользователями, товарами, категориями и атрибутами в админке.

## Конфигурация

Репозиторий содержит исходный код и примеры переменных окружения. Рабочие `.env`, дампы базы, загруженные файлы и секреты в него не входят.

```bash
cp .env.example .env
cp api/.env.example api/.env
cp frontend/.env.example frontend/.env.production
cp admin/.env.example admin/.env
```

Задайте собственные значения секретов и адресов сервисов. Пароль `POSTGRES_PASSWORD` в корневом `.env` должен совпадать с `DB_PASSWORD` в `api/.env`. Для Laravel нужен `APP_KEY`; после установки зависимостей его можно создать командой `php artisan key:generate` из каталога `api/`. Фронтенду нужен `frontend/.env.production` **до сборки Docker-образа**, поскольку его Dockerfile копирует этот файл.

## Запуск

Корневой [`docker-compose.yml`](docker-compose.yml) описывает развёртывание на сервере: PostgreSQL, API, сайт и админку. Он использует внешнюю Docker-сеть `yapp_backend_default`, локальные порты и адреса доменов исходного сервера. Перед запуском в другом окружении настройте сеть и адреса под него.

```bash
docker compose config
docker compose build
docker compose up -d
```

Эти команды предполагают, что переменные окружения заполнены, внешняя сеть существует, а база подготовлена. Данные действующего сайта из одного только репозитория не восстановить. Дополнительные замечания по серверной конфигурации — в [`README-deploy.md`](README-deploy.md).

Для разработки отдельных частей используйте команды из соответствующих каталогов: `composer install` и `php artisan serve` для API, `yarn install` и `yarn dev` для фронтенда и админки. API требует доступной PostgreSQL и настроенного `api/.env`.

## Проверки

- API: `cd api && composer test`
- Админка: `cd admin && yarn build && yarn lint`
- Фронтенд: `cd frontend && yarn build && yarn test --run`

Проверки, которым нужны база или внешние сервисы, требуют отдельного тестового окружения.
